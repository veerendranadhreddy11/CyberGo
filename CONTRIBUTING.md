# Contributing to CyberNex

Use a separate branch and keep changes scoped. Build the frontend and run the Rust storage tests before opening a pull request. Record which installed builds you actually tested.

- Preserve existing mission IDs and checklist positions so study records and backups remain readable.
- Use synthetic examples and keep labs within authorized environments.
- Keep notes, exports, databases, and attached evidence out of commits and screenshots.
- For local-data changes, exercise both upgrade and rollback behavior. Use a forward migration and a test backup.
- Use the [development instructions](README.md#development) for the full set of checks.
